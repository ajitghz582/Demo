Examination Management Portal
Educational institutions require efficient systems to manage examinations involving administrators, examiners, and students. Many institutions still rely on spreadsheets, emails, or manual coordination, making it difficult to manage examination schedules, examiner availability, slot booking, student participation, and evaluation records.

You are required to build an Examination Management Portal (EMP) web application that allows Admin, Examiners, and Students to interact with the system based on their roles.


Frameworks to be used
These are the mandatory frameworks on which the project has to be built.

Flask for application back-end
Jinja2 templating, HTML, CSS and Bootstrap for application front-end
SQLite for database (no other database is permitted)
JS should NOT be used for executing the core requirements
Note
All demos should be possible on your local machine.
The database must be created programmatically (via table creation or model code).
Manual database creation (such as using DB Browser for SQLite) is NOT allowed.

Roles & Functionalities
Admin
Admin is the pre-existing superuser of the application.

Can create, edit or remove courses.
Can create, edit or remove examinations.
Can create and manage examination rubrics.
Can add, approve or deactivate examiners.
Can configure examination timelines.
Can open and close examiner slot creation.
Can open and close student slot booking.
Can view all examination slots.
Can reschedule examination bookings if required.
Can change the assigned examiner in exceptional situations.
Can view all students, examiners, examinations and bookings.
Can search students, examiners, examinations or bookings by name or ID.

Examiner
Examiners are faculty members responsible for conducting examinations.

Can register and log in.
Need Admin's approval to access the dashboard.
Can view assigned examinations.
Can create examination slots during the slot creation period.
Can update or remove slots before booking starts.
Can view students booked for their slots.
Can evaluate students using examination rubrics.
Can submit marks and remarks.

Student
Can register and log in.
Can view available examinations.
Can search and filter examinations.
Can book available examination slots.
Can cancel booking before the booking deadline.
Can view booking status.
Can view examination history.
Can view published results and feedback.

Key Terminologies
Admin
A user with the highest level of access who manages the entire examination system.


Examiner
A faculty member responsible for creating examination slots, conducting examinations and evaluating students.


Student
A registered user who books examination slots and appears for examinations.

Maximum Marks

Core Features
1. Authentication
Login system for Admin, Examiners and Students.
Registration allowed for Examiners and Students.
Admin must pre-exist in the database (no Admin registration).

2. Admin Functionalities
Admin dashboard must display:

Total number of courses.
Total number of examinations.
Total number of examiners and students.
Total number of examination slots.
Total number of bookings.
Admin can:

Create and manage courses.
Create and manage examinations.
Create and manage examination rubrics.
Approve new examiner registration requests.
Open and close examiner slot creation.
Open and close student slot booking.
View all examination slots.
View all bookings.
Search students, examiners and examinations.
Reschedule examination bookings.
Change examiner assignment if required.

3. Examiner Functionalities
Examiner must self-register and log in.

Examiner dashboard should display:

Assigned examinations.
Created examination slots.
Number of students booked.
Pending evaluations.
Examiner can:

Create examination slots.
Update slots before booking starts.
View booked students.
Evaluate students using rubrics.
Submit marks and remarks.

4. Student Functionalities
Students must self-register and log in.

Student dashboard should display:

Available examinations.
Available examination slots.
Upcoming examinations.
Booked slots.
Published results.
Students can:

Book examination slots.
Cancel booking before the booking deadline.
View booking history.
View examination schedule.
View evaluation remarks.
Edit profile.
Search examinations.

5. Other Core Functionalities
Examiners can create slots only during the slot creation period.
Students can book slots only during the booking period.
Prevent overbooking beyond slot capacity.
Automatically close a slot when capacity is reached.
Ensure examiners can evaluate only students booked into their own slots.
Prevent duplicate bookings for the same examination.
Maintain complete booking history for every student.
Allow Admin to reschedule bookings when necessary.
Allow Admin to change the assigned examiner if required.
Allow Admin to view all historical examination data.

Recommended and/or Optional Functionalities
API resources to interact with examinations, examiners, students and bookings.
Role-based access control using Flask extensions such as Flask-Login or Flask-Security.
APIs can return JSON or be built using Flask extensions like Flask-RESTful.
Frontend validation using HTML5 or JavaScript.
Backend validation inside Flask controllers.
Clean and responsive UI using Bootstrap (no other CSS framework allowed).
Charts for examination statistics (booking trends, examiner workload, examination completion).
Downloadable examination scorecard.
Email notifications for booking confirmation and result publication.
Any additional feature relevant to examination management.
